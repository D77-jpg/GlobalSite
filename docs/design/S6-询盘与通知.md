# S6：公开询盘、管理与通知

## 范围与契约

本阶段只修改 GlobalSite，不调用 GlobalCRM、不读 CRM 数据库，不实现 CRM 询盘投递。CRM 契约及 C1–C4 保持不变。
本站私有 API 以 [foundation.openapi.yaml](../api/foundation.openapi.yaml) 为准，公开接口以 [inquiry-gateway.openapi.yaml](../api/inquiry-gateway.openapi.yaml) 为准。新增 9 个私有操作、2 个公开操作及 2 个预检操作；原有接口仅扩充无限量询盘计数和预览 JavaScript MIME。

## 处理链路

静态表单 → 独立 inquiry-gateway 路由 → 来源/限流/大小/字段/附件/Turnstile 校验 → MongoDB 事务存档 + Task + 计量 → 202 回执 → Worker 去重/垃圾评分 → 持久化通知 outbox → 独立邮件任务。

gateway 与 api 同进程，挂载在主 JSON、身份限流及会话中间件之前；网关拥有独立解析器、CORS、IP/站点限流及错误响应，不使用访客 Cookie。worker 独立进程，沿用任务租约、心跳、owner/fencingToken；失败不撤销已存档询盘。所有组织数据仍受 tenant 插件保护。

公共路由先用随机 32 位十六进制 publicId 定位 InquiryGatewayRoute，只允许该模型在受限上下文中执行带 enabled:true 的精确 findOne；随后恢复组织上下文。该映射只有组织/站点路由元数据，不含联系人或密钥。其他业务模型不能借此跨租户查询。

## 数据与索引

以下模型均有 organizationId、timestamps、tenant 插件；U 表示唯一索引，O 表示 organizationId。

| 模型 | 主要字段 | 索引 |
|---|---|---|
| InquiryGatewayRoute | siteId、publicId、enabled | 全局 U(publicId)，U(O,siteId) |
| InquirySettings | siteId、revision、enabled、privacyReviewed、aiSpamEnabled、notificationUserIds、turnstileSiteKey、secret | U(O,siteId) |
| SiteInquiry | siteId、versionId、submissionId、receiptId、requestHash、secret、notesSecret、emailHash、receivedAt、revision、status、spamScore、classification、reasons、duplicateOf、processedAt、aiResult、notificationStatus、attachmentIds | U(O,siteId,submissionId)，(O,receivedAt desc,_id desc)，(O,siteId,status,receivedAt desc)，(O,duplicateOf) |
| InquiryAttachment | inquiryId、key、mime、bytes、storedBytes | (O,inquiryId) |
| InquiryDedupe | siteId、emailHash、rootId、lastAt、lockVersion、expiresAt | U(O,siteId,emailHash)，TTL(expiresAt) |
| InquiryDelivery | inquiryId、userId、status、attempts、attemptedAt、sentAt、errorCode | U(O,inquiryId,userId) |
| InquiryRateBucket | siteId、key、minute、count、expiresAt | U(O,siteId,key,minute)，TTL(expiresAt) |

SiteDeployment 扩充 origins，记录经过现有发布验证的 canonical、项目 pages.dev 和提供商版本域名。SiteVersion.snapshot.inquiry 冻结 publicId、gatewayUrl、启用状态、隐私版本/路径、已审核公司资料及 AI 开关。旧版本不被重写。UsageRecord/UsageBucket 增加 inquiries，所有套餐上限为 null，仅统计实际新存档数。

联系人、留言、来源、同意记录、产品名称、原始文件名、备注和 AI 结果使用现有 AES-GCM 加密；AAD 绑定组织和对象用途。附件对象本身也加密，数据库只存随机 key 和大小。emailHash、requestHash、IP 桶键为用途隔离的 HMAC，不保存原始 IP/完整 UA。secret 等字段默认不查询；审计只记录动作、操作者和对象 ID。

迁移 s6-inquiries-v1 在启动或 npm run migrate 时部署新模型/索引并记账，可重复运行；不改变已有集合名、数据库名或旧文档。需要 MongoDB 副本集以支持事务。移除版本时应保留历史数据，S6 不提供破坏性回迁。

## 来源与安全边界

- CORS 精确匹配已验证的当前线上域名；历史提供商版本预览只接受其已验证 providerUrl。任意子域、端口、null Origin、未登记域名均拒绝。CORS 不能替代身份识别或机器人防护，非浏览器可伪造 Origin。
- 管理台登录预览通过 HTML 注入 2 小时签名授权，绑定组织、站点、版本、Origin；只通过 X-Preview-Token 发送，不放 URL 或导出 zip。浏览器同源 GET 可能省略 Origin，只有携带有效预览授权时允许回退到管理台 Origin；公开站点仍必须提供 Origin。预检仅返回允许的方法/头，不暴露数据。
- POST 每 IP+站点每分钟 5 次、每站点 60 次；读取每 IP+站点 120 次；网关总 IP 180 次。共享数据库桶适用于多 api；429 带 Retry-After:60。主身份接口限流不变。
- 默认忽略 X-Forwarded-For。只有部署者明确设置 INQUIRY_TRUSTED_PROXY 为受信代理 IP/CIDR 后才采用代理链；无效配置回退为不信任。不要填整个公网网段。
- JSON/唯一 multipart payload 字段最多 24KiB；附件最多 3 个、每个 2MiB，仅 JPEG/PNG/WebP/PDF。图片解码验证、限制像素、去元数据、缩放重新编码；PDF 检查签名，但不宣称已做杀毒。
- 附件走同组织登录下载，强制 attachment、nosniff、sandbox；不提供公共对象路径或匿名下载。存储容量不足会拒绝带附件的提交，询盘计数本身从不拦截。
- 蜜罐命中仍存档并标记。Turnstile 可选、秘密加密；启用后服务端验证 success、hostname、action=inquiry、cData=publicId，使用 submissionId 做验证幂等键；失败不存档。
- pageUrl 必须是对应版本的合法页面，referrer 去除查询/片段；保留 UTM 五项。国家为访客填写，不推断地理位置；设备仅保留 desktop/mobile/tablet/unknown。拒绝可选存储时首次访问时间仅取本次页面打开时间。

公开响应只返回 received 与随机 receiptId，不泄露联系人、内部询盘 ID、垃圾评分或处理结果。网关及私有询盘响应均 no-store。

## 幂等、垃圾识别与通知

相同 submissionId + 规范化内容/附件散列返回原回执；同 ID 修改内容返回 409。唯一索引及事务保护并发；只写一次任务、询盘数和用量记录。文件先写私有存储，事务失败/重放时清理本请求新文件及其计量。

Worker 以规范化邮箱 HMAC+站点执行 10 分钟滑动窗口归组，保留每条记录、留言、附件和计数；列表默认隐藏重复条目，详情可查看合并留言。不同组织、不同站点不合并。TTL 仅清理辅助去重桶，绝不删除询盘。

spamScore 越高越可疑，>=80 将仍未人工修改的新询盘标记为垃圾。蜜罐、链接密度和推广词规则始终可用。AI 默认关闭；启用后只向组织配置服务商发送经邮箱/电话/URL 基础遮盖的留言，不发送联系人字段、附件或组织事实。自然语言可能仍含个人信息，隐私模板需说明并由运营审核。结果先加密保存再结算额度；重试复用已保存结果。额度不足/未配置/调用失败回退规则，未知计费不自动重新调用。

配置收件人必须是当前组织活跃成员；未指定时使用组织负责人，发送时复查成员与邮箱验证。每收件人独立 InquiryDelivery + Task；邮件只含固定通知和登录详情链接，不含访客正文/附件。SMTP 已知拒绝按现有 Worker 退避最多 8 次；成功不重发。网络结果不明保留 attemptedAt 并停止自动投递，避免盲目重复；后台展示状态。开发无 SMTP 只记录通知编号，生产无 SMTP 显示 blocked 并等待重试，不影响主功能启动。已知失败/未配置/开发通知支持后台重试；running 任务不能重置。收件人全部失效时标记 no_recipient，已存档询盘仍可管理。

## 前端与静态站

站点工作区新增“询盘设置”，管理员审核隐私政策、启用表单、选择通知成员、可选 AI/Turnstile。设置修改有审计与 revision 比较。启用/政策公司资料变更后必须重新构建发布；运行时关闭立即阻止新提交。

静态页包含姓名、公司、邮箱、国家、电话/WhatsApp、多产品选择、数量、留言、附件、隐私同意和隐藏蜜罐。原生验证+可聚焦错误摘要；失败保留输入，成功显示已存档回执。关键页面内容仍为静态 HTML，询盘提交需要可信的增强脚本；无 JS 时明确提示，不静默丢单。

自动生成隐私页及 sitemap 条目，路径冲突使用 /legal/privacy-policy 或后缀。只在管理员确认政策后带入已确认公司名称/地址/联系资料；引用参与 S5 事实版本门禁。所有访客都显示同等可见的允许/拒绝选项，拒绝不影响询盘。默认不加载任何可选统计，只有同意后才保存本站首次访问时间；选择与站点 namespace 绑定，可随时打开偏好。该模板不构成特定地区法律合规保证。

管理台支持站点/状态/垃圾评分/日期筛选、分页、重复开关、详情、四状态、备注、附件下载和 CSV。管理员/编辑可跟进，所有角色可查看本组织；配置仅管理员修改。导出最多 5000 行，超限需缩小筛选，沿用 CSV 公式注入防护。中英文文案集中维护。

## 部署限制与后续

生产 PUBLIC_URL 必须是可公开访问的 HTTPS 管理台/API 地址，api、worker 共享同一密钥和持久化私有存储；发布启用询盘的版本前验证网关 HTTPS/公开地址，防止上线产物指向 localhost。反向代理须同时转发网关路由并允许约 6.1MiB 上传，不能缓存接口。

zip 可离线导出；本阶段匿名 CORS 域名授权依赖已完成的 Cloudflare 发布记录，单纯把 zip 上传到未登记主机不会自动开放询盘。后续如需其他托管，应新增域名所有权/部署验证流程，不能放宽任意 Origin。

尚未实现附件杀毒、数据保留/删除后台、真实国家地理识别、无有效收件人时为历史记录新增收件人、未知 SMTP 结果的提供商回执对账。这些限制不能导致已存档记录被丢弃。CRM 推送留给后续明确授权阶段。
