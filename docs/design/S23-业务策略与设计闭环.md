# S23 业务策略与设计闭环

本任务只修改 GlobalSite，分支 `feat/s23-business-design`。GlobalCRM 的代码、数据库和 Integration API 契约不变。[验收记录](../verification/S23-验收.md)。

## 审计与目标

原流程把工业采购栏目套到不同业务；Agent 无法明确确认购买路径，两个首页不足以检验详情页；渲染器追加目录导致重复；布局指令可能被旧 CSS 覆盖；截图审查与修订缺乏直观前后对照。

本次以“业务解释 → 确认规划 → 两套首页/代表详情 → 选择 → 截图检查/修订 → 人审 → 扩展整站”为闭环。保留已有业务能力、真实资料、组织隔离、用量与发布门禁，不自动公开试点。

## 1. 业务判断与可审核规划

`plan.strategy` 保存 offering、buyingJourney、decisionFactors、navigation、productSections、visualPriorities、questions。购买路径为视觉选型、技术选型、定制采购、咨询；行业描述自由输入，不增加固定行业模板枚举。

研究任务依据产品、目标市场、已确认事实和用户资料生成策略；不能把上一版策略当成新一轮必须遵循的指令。策略与站点地图在原确认流程中共同审核，导航标签可修改且只能指向实际规划节点。缺失的适用资料集中为访谈问题。

视觉选型不会在没有对应确认事实时强制 MOQ/OEM/认证；技术选型保留规格、材质、应用；定制采购保留材质、定制、数量与样品等决策问题。旧计划缺少 strategy 时仍执行原栏目要求。策略是业务解释，不是企业事实，公开导航与内容的数字、认证等仍必须通过事实校验。

## 2. Agent 布局与可信渲染

每个区块可保存 `design`：purpose、frame、ratio、fit、focus、density。框架提供画廊、索引、故事、双栏、步骤、表格与通栏；比例、裁切与焦点使用受控白名单。模型不能提供 CSS、HTML 模板、脚本或执行代码。

渲染器处理已验证的组合规则：保留 Agent 明确选择的目录顺序；已有发现区块不再追加同一产品目录；空产品区块省略；无图双栏转为紧凑单栏；非图片内容误选 gallery 时改用索引/步骤/表格。图库和索引的图片、标题、说明显式定位，图片 contain 意图优先于通用首屏样式。旧 line-sheet 行为保持兼容。

规格表只有在所有值均为明确“待确认”占位、没有引用或数字声明时，才合并成原有资料确认区；真实参数、数字和引用绝不删除或补造。输出仍经过重复内容、内容深度、组合差异、链接、FAQ、适用栏目和事实校验。

## 3. 四页试点与恢复

新策略按 primary-home、primary-detail、alternate-home、alternate-detail 四个持久 Worker 单元执行，每个单元只生成一个页面。每单元沿用既有最大三次格式/内容修正、输出预算与未知计费暂停规则。四页完成后聚合成兼容的 directions 响应；旧冻结单包/成对任务仍按原结构处理。

两方向必须在设计轴及实际区块安排上具有差异，不能只换颜色。前端同时比较两方向，可切换首页/代表详情和桌面/手机。

失败或取消后可显式使用 `reuseRunId` 创建新任务，仅复用同站点、同来源快照和同页面修订的已完成成果；原任务历史与费用保留，新任务只生成剩余页，并要求新的用量同意。结构完整但内容不合格的候选按组织/任务/单元独立用途加密，不进入 DTO、日志或浏览器。候选经过有限组件兼容处理并重新通过全部门禁后可以复用；存在未知计费 operationId 时不能走免费复用分支。

JSON 解析新增锁定依赖 jsonrepair 3.15.0，只修复完整对象的语法；拒绝截断、多对象歧义、表达式及数值词元变化。之后仍执行原业务与事实校验，不把语法修复当事实补全。无其他依赖升级。[官方来源及许可](https://github.com/josdejong/jsonrepair)。

## 4. 人工选择、截图与修订

选用方向在同一事务复查首页、详情页修订及来源，保存两页待审草稿，不自动批准。选用后仍保留提案；试点未被编辑时可以切换方向，已经编辑则拒绝覆盖。

整站默认扩展要求试点两页当前内容已批准，并存在管理员确认的对应截图审查，内容哈希和规划修订必须匹配。明确指定页面的修正任务仍可运行；整站扩展保留已审核试点。修改内容后原审核失效。

截图服务在隔离构建中实际打开 375/768/1440 页面，记录坏图、溢出、重复标题、发现区块、区块尺寸、图片比例与裁切。修订先保存已计费模型收据，再生成稳定 after 截图；恢复不能重复调用模型。工作面板显示 before/after，修订结果始终待人工复查。

模型支持图像输入时传真实桌面/手机图；不支持时明确标注文字/结构检查，不能宣称看过图像或达到审美标准。VELATURO 当前模型不支持图像输入，本轮采用真实截图测量及人工实图复核。

## 5. 数据、API 与部署兼容

本站 OpenAPI 先更新：plan.strategy、block.design、代表详情提案，以及预览 page、截图 phase、AgentInput.reuseRunId。均为原接口扩展，无新增端点或 scope。唯一 CRM 对接契约不变。

无新模型、集合、索引、环境变量或数据迁移。新增字段为可选字段，现有任务步骤的候选收据为加密私有数据；旧页面、任务、静态 zip 不改写。新生成策略使用 brand-site-v4。构建和预览共用 composition.css。

## 6. 可复用验证与边界

油画侧重作品/空间/私人需求及询价，机械侧重技术选型和规格应用，箱包侧重材料/定制/打样；三者回归使用隔离合成资料验证结构和事实门禁。VELATURO 使用已有真实上传资料走真实模型和 Worker，保留旧站作对照。合成性能分数只衡量合成测试产物，不能代表真实站的审美或商业效果。

本轮只完成两套四页提案，不直接覆盖旧整站或公开发布。用户选定方向、确认事实和试点审查后，再扩展整站。真实素材仍缺商业规格/交易条款，应集中补充而非编造。
