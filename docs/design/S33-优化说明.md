# S33 优化说明（已确认实施版）

> 目标：在不破坏现有安全、多租户、计费与事实门禁的前提下，提升 **AI 生成成功率与质量、生成速度、代码可维护性、上手体验与 S32 视觉成片一致性**。
> 约束沿用 AGENTS.md：不升级无关依赖；API 变化先改 `docs/api/foundation.openapi.yaml`；完成 `typecheck` / `build` / `lint` / `test`，前端改动跑 Compose + `test:e2e` + `test:quality`。
> 分支：`feat/s33-agent-quality`（自 `feat/s30-flagship-ux-rearchitecture` 切出）。

---

## 一、现状诊断（依据代码实测与 S22/S23/S32 验收）

| 问题 | 实测证据 | 影响 |
| --- | --- | --- |
| 模型输出诊断不足与无严格模式 | 已使用 `response_format: json_object` 与受限 `jsonrepair`（数字不变校验 + zod）；S22 (`1132021`) 去重提示词并扩展 `32768/240s` 后分类页可一次成功，但缺少 `invalidReason` / 修复率量化、缺少可选 `json_schema` 严格子集模式、缺少任务级采样参数 | 难以按数据定位模型弱项；局部单区块不合格时需整页重做 |
| 单一模型无任务路由 | 组织仅配置一个主力模型与可选 `visionModelName`，研究/访谈/撰写/视觉审查未按性价比与能力自动分流 | 简单步骤成本高、视觉审查闭环未充分激活 |
| AI 视觉导演与 S32 引擎未完全对齐 | S32 已提供 9 套配色、4 套本地 OFL 字体与 4 种首屏构图，但提示词与生图提示词尚未按行业自动绑定配色/构图/`fit-cover` 与暗/亮调光影规则 | 易出现 `panorama` 配 `fit-contain` 灰边或暗黑站配白底图等违和效果 |
| 核心文件过大与类型松散 | `site-agents.service.ts` 2348 行 / 91KB；`web/src/sites.tsx` 3764 行 / 138KB；核心链路存在大量 `any` | 改动风险高、提示词与步骤难独立演进 |
| 前端样式层叠债务重 | `web/src/main.tsx` 串联导入 18 份历史 CSS，打包出 268 KB `index.css`（注：JS 主包已由 S27 拆至 62 KB，非 >500 KB） | 样式规则重复冲突、维护成本高 |
| 流程重与首页预算缺乏约束 | 从建站到可预览步骤多；缺乏首页区块上限与页面高度预警 | 外贸用户上手门槛高；首页易过度拉长 |
| 仓库本地杂物与 README 冗长 | `.cache/` 遗留本地扫描文件；README 历史记录偏长 | 本地噪音大、新成员阅读负担重 |

## 二、优化项与实施方案

### M1：P1-1 拆分 `site-agents.service.ts` + P1-2 核心类型收紧 + 诊断基建

1. **目录拆分（对外导出与行为 100% 兼容）**：
   ```
   server/src/services/agents/
     types.ts            AgentRun / AgentStep / InputSnapshot / Diagnostics 强类型
     billing.ts          用量预留 / 结算 / 未知结果暂停
     runtime.ts          fenceRun / ownRun / 活动锁 / 调度辅助
     prompts.ts          提示词组装、预算与 S32 视觉导演规则
     validation.ts       区块与组合校验、首页预算/高度诊断
     steps/research.ts   research / interview 步骤
     steps/design.ts     design / content 步骤与单区块局部修复
     steps/review.ts     review / refine 步骤
     steps/rewrite.ts    section rewrite 步骤
   server/src/services/site-agents.service.ts  保留对外聚合导出（路由与测试零破坏）
   ```
2. **类型收紧**：优先消除 `server/src/services/agents/**`、`site-agent-provider.service.ts`、`agent-json.service.ts` 的 `any`。
3. **解析诊断埋点**：`parseAgentJson` 返回 `repaired: boolean` 与枚举化 `invalidReason`（不存模型原文与密钥），记录“修复后通过 / 截断 / 非 JSON / 业务门禁驳回”统计。

### M2：P0-1 输出可靠性增量 + P0-3 任务模型路由 + 局部区块修复与首页预算 + S32 视觉导演对齐

先更新 `docs/api/foundation.openapi.yaml`，再实现与补齐真实 HTTP 契约测试：

1. **可选严格 `json_schema` 模式与自动回退**：
   - `AgentAiProvider` 新增可选 `outputMode: "json_object" | "json_schema"`（默认 `json_object` 兼容现状）。
   - 提供专门的 `toStrictOpenAiJsonSchema()` 扁平严格子集转换器（强制 `additionalProperties: false`、全量 `required` + 可选转 `nullable`、剥离上游不支持的约束关键字），并配单测卡住不合法语法。
   - 上游返回 400 不支持 `json_schema` 时自动回退 `json_object` 一次且零重复计费。
2. **任务级采样参数与任务模型路由**：
   - 新增可选 `temperatureByTask`（默认为空不发送，兼容推理模型）与可选 `taskModels`（`research` / `interview` / `design` / `content` / `review` / `rewrite`，留空回退 `modelName`，`review` 附图片时优先 `taskModels.review ?? visionModelName ?? modelName`）。
   - 审查报告显式标注 `reviewMode: "visual" | "structural"`；用量统计保留按模型维度汇总。
3. **首页区块预算、估计高度校验与失败区块局部修复**：
   - 首页内容区块默认预算 `<= 8` 且引入基于区块权重的估计高度提示，避免 6000–7000px 过长页面。
   - 整页校验若仅 1–2 个具体区块触发内容/深度/格式问题，复用受控局部修复路径仅重修目标区块（在既有单元重试预算与计费围栏内执行），不再无脑丢弃整页。
4. **AI 视觉导演对齐 S32 引擎**：
   - 更新 `server/agent-skills/brand-site.md` 与 `design` / `content` / 生图提示词：按行业自动选择 S32 9 套配色与 5 套字体、`panorama` 首屏非装裱艺术品默认 `fit: "cover"`、优先启用有已确认事实支撑的 `metrics` / `certifications` / `gallery` / `showcase` 旗舰区块，并让概念配图提示词同步匹配站点暗黑/暖白/工业光影基调。

### M3：P1-3 前端模块化瘦身与 AI 路由配置 UI

1. **拆分 `web/src/sites.tsx`（3764 行）**：按职责拆分为 `web/src/sites/` 子模块（概览/向导、内容与编辑、设计提案、质量审查、任务状态、公共类型与辅助函数），保留 `web/src/sites.tsx` 聚合入口与全部现有导出兼容。
2. **合并瘦身 18 份历史 CSS**：清理未引用/被后续覆盖的旧版重复规则，显著压缩 `index.css` 体积并保持 Velvet Obsidian 暗/亮双主题与严格 CSP（`style-src 'self'`、零内联样式）无回退。
3. **AI 设置页面增量**：补齐 `outputMode`、`taskModels` 与 `temperatureByTask` 的中英文表单配置与单测。

### M4：P2-1 一键出站快速通道 + P2-2 多行业基准 + P3 仓库整理

1. **“一键出站”快速通道 (`POST /api/v1/sites/:id/fast-track`)**：
   - 先更新 `foundation.openapi.yaml`；允许管理员或编辑在显式 AI 同意下，从新建站点向导直接触发“研究规划 → 提案/内容生成 → 结构审查”的受控串联通道（或由前端与后端状态机分步驱动既有受限任务），目标快速产出可登录预览版本。
   - **安全门禁零放松**：未确认事实保持 `candidate` 不进入商业声明，正式商业发布仍须人工确认事实、管理员批准页面与接受质量审查报告。
2. **多行业回归基准 (`scripts/s33-benchmark.mjs` + `docs/verification/S33-多行业回归基准.md`)**：
   - 覆盖 4 类典型外贸行业（精密机械、商业咖啡设备、可持续包装、清洁能源储能），固定输入快照验证 S32 渲染、首页区块数/高度、HTML 校验、375/768/1440 零溢出与解析修复率。
3. **仓库整理**：精简 `README.md` 并将分阶段演进摘要归档至 `docs/CHANGELOG.md`；安全核查本地 `.cache/` 残留并按需清理无用二进制缓存。

## 三、不做的事

- 不改 GlobalCRM 契约与连接逻辑；不升级 React Router 7 / Express 5 / 无关依赖。
- 不放松事实门禁、审批门禁、多租户隔离、CSRF 与鉴权；不改动历史计费记录与旧版本 zip。
- 不删除 `storage/` 中的真实素材、数据卷或用户数据。
