# S28 外贸增长运营、多渠道发布与对象存储适配

## 1. 目标与边界

本阶段面向外贸独立站上线后的获客、转化、SEO 与多平台运维场景，同时严格坚守 GlobalSite 的多租户隔离、事实门禁、零内联脚本注入、Cookie 同意合规与无新依赖原则。

- 仅修改 GlobalSite；GlobalCRM 无新增接口或代码依赖。
- 所有新增或扩展的私有 API 均先行写入 `docs/api/foundation.openapi.yaml`，并通过真实 HTTP 契约测试验证。

## 2. SEO、分析统计与 301 重定向

- `PublishingSettings.seoAnalytics` 支持配置：
  - `ga4MeasurementId`（`^G-[A-Z0-9]{6,16}$`）
  - `gtmContainerId`（`^GTM-[A-Z0-9]{4,12}$`）
  - `metaPixelId`（`^[0-9]{8,20}$`）
  - `googleSiteVerification` / `bingSiteVerification`（输出 `<meta name="google-site-verification">` 与 `<meta name="msvalidate.01">`）
  - `ogImageAssetId`（必须属于当前组织已就绪图片资产；`removeAsset` 禁止删除仍在使用的 OG 封面图；`buildStatic` 打包并覆盖页面 `og:image` / `twitter:image`）
  - `redirects`（最多 100 条 `301`/`302` 规则，严格校验路径/HTTPS 目标并禁止换行与空格注入；静态构建时输出标准 `public/_redirects`）
- **Cookie 同意门控**：静态 HTML 不直接内联第三方追踪 `<script>`，仅在 `<body>` 写入校验后的 `data-ga4-id` / `data-gtm-id` / `data-meta-pixel-id`。`server/builder/inquiry.js` 仅在访客明确同意可选 Cookie（`choice.value === "optional"`）且**非登录预览**时才加载官方域名分析脚本；拒绝可选 Cookie 时零追踪请求且不影响正常浏览与询盘提交。

## 3. 访客自动确认邮件与询盘转化汇总

- `InquirySettings` 新增可选 `autoReplyEnabled`、`autoReplySubject`、`autoReplyBody`。
- `processInquiry` 对非重复、非垃圾（`status !== "spam"`）询盘且启用自动回执时，在事务内入队 `inquiry.autoreply` 任务（运行于 Worker `fast` 车道）。
- 自动回执任务复用 `fenceTask` + `autoReplyAttemptedAt` 防重机制：未知 SMTP 结果停止自动重发，已知 SMTP 错误按退避重试；邮件仅包含管理员确认模板与 `receiptId`，**绝不回显访客原文**以防止邮件反射滥用，日志不记录访客邮箱或正文。
- 新增 `GET /api/v1/inquiries/summary`：在当前组织上下文内返回有效询盘数、各状态分布、跟进处理率、近 30 天日趋势及脱敏 Top 来源统计（UTM source 或 referrer 域名）；管理台询盘收件箱顶部展示转化漏斗概览条。

## 4. 域名诊断与多渠道部署 Webhook

- `POST /api/v1/sites/:id/domain-check` 保留原有 `status`/`domain`/`checkedAt` 字段兼容，并新增结构化 `diagnostics`（`dns` / `cloudflare` / `https` 分步状态码）与 `recommendedRecord`（推荐 CNAME 记录），方便运维快速排查 DNS 与 HTTPS 状态。
- `PublishingSettings` 新增可选公开 HTTPS `deployWebhookUrl` 与加密存储的 `webhookSecret`；管理员可通过 `POST /api/v1/site-versions/:id/webhook` 触发已通过 `validVersion` 门禁的就绪版本 Webhook（经 `publicUrl` SSRF 校验、禁重定向，附带 `X-GlobalSite-Event` 与可选 `X-GlobalSite-Signature: sha256=...` HMAC-SHA256 签名），便于对接 Vercel / Netlify / S3+CloudFront / 自建 CI。

## 5. 可选 S3 / Cloudflare R2 对象存储适配

- 新增零外部依赖的 `server/src/services/object-storage.service.ts`（纯 Node `crypto` 实现 AWS Signature Version 4，支持 `PUT`/`GET`/`DELETE` 与租户前缀隔离 `${S3_PREFIX}/${organizationId}/${key}`）。
- `STORAGE_DRIVER` 默认保持 `local`，现有本地持久卷完全兼容；设为 `s3` 时，`storage.service.ts`（资产与构建产物）与 `inquiry.service.ts`（私有附件清理）无缝切换至 S3/R2 兼容对象存储，保留原有 `storage_bytes` 计量与事务回滚逻辑。
