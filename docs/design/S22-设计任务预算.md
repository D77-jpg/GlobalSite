# S22：双首页设计任务预算

真实建站执行发现：规划任务可完成，但设计任务在已有 16384 输出 Token 上限下连续返回 finish_reason=length。设计任务需要同时输出两份完整首页 JSON，部分模型的推理也占用同一输出预算；这与单页内容任务的需求不同。

本次只修改 GlobalSite：
- design 使用 32768 的有界输出上限与 240 秒请求总时限。
- content/refine/review/rewrite/research 的预算及 120 秒时限不变。
- 增加的预算由现有 UsageRecord/UsageBucket 原子预留，仍按实际用量结算。
- Worker 每20秒续租及 owner/fencing 继续生效；没有延长已失效任务的权限。
- 长度截断仍是已知计量的格式失败，最多三次修正；超时/未知结果继续暂停并保留预留，不自动重放。
- 不放宽 JSON、事实、双提案差异、内容深度、人审及发布门禁。

没有 API 字段、端点、scope、环境变量、数据模型或迁移变化。失败历史保留；调整后的新任务使用新预算。

测试：配置模型调用捕获 design/content 请求的不同输出上限和截止时间，并核对设计任务的额度预留与结算；原有未知用量与有限重试测试继续执行。真实模型重试在修复部署后通过产品 UI 发起，资料与产出只保存在本机工作空间，不提交素材或业务内容。
