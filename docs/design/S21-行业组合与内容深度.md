# S21：采购驱动的行业组合与内容深度

## 范围与结论

只修改 GlobalSite，不修改 GlobalCRM、CRM 契约或数据库。用户要求改进产品内 Agent 的生成能力，不是手工装修某个演示站。

现有瓶颈：visualStyle 只有三项、heroLayout 只有两项，标题和首屏精简规则占主导；参考读取主要截取开头正文，容易把复杂站点变成短目录；未以内容深度阻止过薄结果；导航只保留部分购买页面，其他有效页面被隐藏。这不是颜色的问题。

本次以多轴设计组合、逐页采购决策和生成校验解决；保留来源确认、逐页审核、版本不可变与安全构建。

## 四个标杆的可迁移原则

研究日期：2026-11-09。依据官方网站公开静态页面；浏览器检查本次超时，不能把静态分析称为像素级视觉审计。用户提供的截图辅助理解方向。不复制原站文案、图片、商标、客户、数字或科学/商业结论。

| 官方来源 | 可学习的组织方式 | GlobalSite 对应能力 |
| --- | --- | --- |
| [RapidDirect](https://www.rapiddirect.com/) | 工艺能力、材料、应用与工程资料分层；从需求到报价形成清晰路径 | capabilities 导航、参数列表、比较、采购需求准备 |
| [Komaspec](https://www.komaspec.com/) | 按制造/装配业务组织服务，区分买家阶段，连接工厂与项目证据 | solutions 导航、服务范围、过程与有依据的项目内容 |
| [PakFactory](https://pakfactory.com/) | 产品类型、使用行业、选项、设计、样品和交付形成采购链条 | catalogue 导航、类别网格、选型内容、定制与样品问答 |

这些是信息组织原则，不能推导“用户也拥有相同能力”。如无工厂/认证/案例资料，Agent 记录缺口并追问，不能制造证据页。

## 设计组合，避免行业枚举无限增长

新增可选 SitePresentation.composition；选用提案后同时冻结到 Site.designDirection：

- version: v1。
- typography: sans / editorial / technical。
- palette: graphite / cobalt / clay / forest / violet。
- navigation: catalogue / capabilities / solutions。
- productLayout: cards / rows / gallery。
- heroLayout 在 split / stacked 之外增加 editorial / panorama，按内页用途选择。

各轴独立组合。四类采购模式是 Agent 的推理起点，不是“只有四个行业模板”：
工程选型、可配置产品系列、材料品牌、项目解决方案。陌生业务按客户决策、证据和图片条件组合，不能根据旧 templateId 强制匹配行业。

规则全站共享，内页可以选择适合其目的的首屏。选定设计的字体、配色、导航与产品展示写回整站生成；其他页面不能自行换一套设计。前端保留新首屏的编辑与既有配置兼容性。

CSS 仅使用可信、本地组件，所有类名来自白名单。使用系统 sans/serif/monospace 字体，无新增远程字体或运行依赖。新组合的样式受 composed-site 作用域约束，不把旧内容强行改成新设计。

## 页面与内容规划

研究任务接收 compositionBrief：采购模式、逐页问题、建议内容目标、证据限制。每个页面仍使用已有 brief 的 purpose、buyerQuestions、requiredFactTypes、sections。规划应根据真实目录规模建立产品家族、应用、资料、公司和联系路径；不能为了页数建立无资料的空页面。

首页目标为 6–10 个有用途的区块，证据充足时约 400–800 个有用英文词。重点是：
报价对象与买家、产品/能力发现、选型标准、应用背景、采购准备、真实证据、下一步。
产品页回答规格、材质、应用、可选项与边界、采购条件；分类页回答选择与比较；方案页回答适用问题和范围。篇幅是指导而非填充许可。

新的 B2B v3 生成结果必须携带 composition：
- 首页至少五个实质区块、260 个正文词、发现入口、选型解释、流程或 FAQ。
- 产品/其他页有较低正文下限；已有产品事实和必需区块门禁继续生效。
- 安全占位语不计入篇幅；重复正文和重复目录区块不计作内容丰富。
- 过薄结果作为已知格式失败，先结算用量，再按已有最多三次预算修正；不重复未知结果。
- 两套新 B2B 提案需要至少两个结构轴不同（字体、导航、产品展示、首屏）；单换颜色不算不同方案。
- 同一规则也用于带 composition 页面的审批前检查，不能编辑成空页面再发布。

内容检查是底线，不证明文案优秀。仍需真实截图、人审、refine 及事实确认。生成的中性采购指导必须表述为买家应该提供/核对的信息，不能悄悄变成供应商服务承诺。

## 参考研究与导航

运行时仍最多三个参考站，不改变 robots、SSRF、公开 IPv4 固定、无脚本/无 Cookie 规则。
新增静态结构证据：同源导航标签/路径、h2/h3 区块及大致文字/图片数量；不发起子链接请求，不抓取图片，不执行脚本。不再把开头的竞争对手正文作为学习材料。研究结果标记 static_html_only，不能声称读取了视觉效果。

新组合的导航按 Products/Capabilities、Solutions、Company、Resources、Contact 分组：
同组所有实际页面均可进入，单一目的地直接链接，多项使用键盘可操作的 details 菜单。
不生成空壳入口，不以增加顶层条目解决问题。页脚提供真实页面的补充入口。

## 契约、兼容与迁移

先更新 docs/api/foundation.openapi.yaml，再实现 validators、选择提案、生成与渲染。
没有新增 HTTP 端点，没有 CRM API/scope 变化，没有新集合/索引/环境变量，不需要迁移。

旧页面缺少 composition 时沿用原审批规则；历史冻结任务保留原技能版本。历史构建 zip/已部署版本不改写。新规则需要重新生成/选用提案、审核、构建后才体现在旧站点的新版本中。

新版技能是已有锁定来源的本地审核适配 v3；未远程执行上游技能，没有新增第三方代码依赖。

## 验证与实际边界

- HTTP 契约与 Worker 处理器：四类虚构业务，首次薄输出被拒、计量后修正、结果持久化、跨组织不可见。
- 提案选择：共享组合冻结并传播，旧内容/人审门禁保留。
- 单元：白名单、事实门禁、稀疏/重复内容、陌生业务模式、静态参考结构和危险链接过滤。
- 构建：旧四类样例及新增四套组合均运行 HTML 校验、375/390/768/1440 响应式检查与移动 Lighthouse。
- 截图为隔离合成素材的渲染测试，不是商业成品或真实模型的审美评分。
- 本任务不调用真实付费模型；真实模型是否稳定生成达到标杆水平的内容，需后续在用户选定的真实业务和已确认资料上持续评估。不能以测试全绿宣称已全面达到头部品牌站水准。
- 后续优先：积累经过人工选择的提案/修订对照样本、按页面采购问题做更细的语义评估、增加组织自有素材和证据，逐步扩展组件组合。
