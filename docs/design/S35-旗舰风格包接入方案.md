# S35 旗舰风格包接入方案

> 目标：让 GlobalSite 自动生成达到 `storage/verona-sample/` 样站水准的独立站。样站即质量基线。
> 原则：复用现有区块类型和事实门禁，新增"风格包"而不是重写渲染器；每阶段独立提交，旧站不受影响。

## 现状要点（代码核实）

- 渲染：`static-template.service.ts` 把 `composition` 各轴转成 body 类（`composed-site type-* palette-* ...`），样式在 `builder/site.css + composition.css`，由 `static-builder.service.ts` 合并打包。
- 字体：构建产物禁止外网（`no-network.cjs`），字体必须本地打包在 `builder/fonts`（OFL）。
- 区块类型已有 metrics、product-grid、split、features、gallery、case-study、customization、cta 等，足以映射样站 9 块。
- 图片：`image-studio.service.ts` 已有 `generateImage`（gpt-image-1 等），Asset 模型已有 `generatedConcept` 字段，但只在资料库手动调用，Agent 不会自动配图。

## 阶段

### A. 渲染风格包 `precision`（视觉收益最大）
- `composition` 新增可选轴 `pack: "precision"`（zod + OpenAPI），body 增加 `pack-precision` 类；未设置时完全保持现状。
- 新增 `builder/pack-precision.css`（作用域 `.pack-precision`），按样站规则：窄体大写标题 + 衬线正文、区块明暗自动交替、满幅首屏渐变遮罩、metrics→数据带、product-grid→机型大图阵列、features(gallery/story)→场景分流、split→配套推荐、gallery→工艺三联、case-study→客户故事、直角大写按钮、询盘区。
- 本地打包 Barlow Condensed / Barlow / Source Serif 4（OFL），更新 SOURCE 与许可证。
- 生成规则：设备/机械/五金类优先选择 `pack: precision`，并给出首页 9 块骨架与样站文案示例。

### B. AI 自动配图
- 设计步骤结束后，对缺图的首屏、机型、场景、工艺区块调用 `generateImage`，存为 `generatedConcept: true` 的 Asset，替换 assetId；前台标注"示意图"。
- 未配置图片服务时跳过，不影响生成。按组织额度计费，复用 reserve/settle。

### C. 演示数据模式 + 候选事实（已决策：两者都做）

决策（2026-11-25）：预览用演示模式，正式上线前所有 AI 补充数据都要人工确认。

- **统一来源**：AI 补充的数据一律写入现有 `FactSheet`，`status: "candidate"`，`source: { kind: "ai-suggested", runId }`，与人工资料同表，不新建集合。
- **演示模式**（站点级 `demoMode: boolean`，默认 false）：
  - 开启后，Agent 输入快照与页面校验把 `ai-suggested` 的候选事实视同可引用，仍走全部数字/年份/认证/禁用词校验；
  - 预览页脚与后台显示"演示内容，未经企业确认"；
  - 发布无需新增拦截：`publishing.service.ts` 现有门禁要求版本引用的每条事实 `status === "confirmed"`，引用候选事实的版本会以 `VERSION_FACTS_CHANGED` 被拒，界面需把该情况翻译为"含未确认的演示数据"。
- **正式确认**：事实库新增"AI 建议"筛选，支持逐条/批量确认、修改或拒绝；确认后改为 `confirmed`，revision 递增，原页面引用需重新生成或通过"按审查改进"刷新。
- **关闭演示模式**：仅允许引用已确认事实，未确认的演示数据在下次生成时不再进入输入。
- 实施顺序：在阶段 A、B 完成并通过测试后进行，避免与风格包改动同时修改 `sites.validator.ts`、`prompts.ts`。

### D. 质量基线审查
- 质量审查截图与样站基线并排，按首屏冲击、节奏、信息密度、可信度、转化路径五项打分，低于阈值进入"按审查改进"。

## 验收
- 重新生成 Verona（选择 precision 包、开启演示模式、配置图片服务），首页与样站并排对比，人工评分不低于样站 80%。
- typecheck / build / lint / test 通过；未选择风格包的旧站 HTML 与 CSS 输出不变。

### 阶段 B：AI 自动配图
- 新增 `server/src/services/agents/auto-images.ts`（`planImageSlots` / `applyImageSlots` / `fillUnitImages` / `autoImageCaps`）。
- **接入点（选择理由）**：在 `site.agent` Worker 单元内、模型结果已持久化并结算之后、`applyUnit` 之前执行（`process.ts` 两处：正常路径与失败候选复用路径）。复用该单元的任务租约、fence、取消与续跑；生成的资产 ID 先以 fenced 事务写入 `steps[i].generatedImages`，再注入页面；计费操作号按 `run + slot` 固定（`image:auto:<runId>:<hash>`），续跑时已持久化的槽位直接复用，未知结果的预留不会被重复支付（`reserve` 返回已存在时跳过并记 `IMAGE_ALREADY_SUBMITTED`）。
- **默认关闭**：仅当站点 `autoImages=true`（管理员开关）且组织已配置 `images` 服务时执行；否则返回原结果，不发请求、不计费。
- 槽位优先级：首屏（填入空 image 区块，或在首位插入 image 区块）→ split 配套 → gallery 工艺 → features 场景（每区块最多 3 张）→ product-grid 机型卡（仅当对应产品没有任何图片）。只填缺图，不覆盖已有图片。
- 每页上限：`AUTO_IMAGE_HOME_MAX`（默认 6）、`AUTO_IMAGE_DETAIL_MAX`（默认 3），取值 0–12。
- 只在页面除图片外没有其他校验问题时才生成（避免为必然失败的草稿付费）；填图后若校验问题增加则整体回退（事件码 `IMAGE_FILL_REVERTED`）。
- 提示词：`image-studio` 的 shots + `paletteAtmosphere`（按 `composition.palette`）+ 区块用途 + “No people, no human faces or hands, no readable text, letters, numbers, labels or logos”。
- 复用：`Asset` 新增 `originKey`（组织内唯一部分索引）；同一站点/节点/槽位/配色/主题的 originKey 命中已就绪的生成资产时直接复用。
- 失败（未配置、额度不足、请求失败、响应无效）只记录固定事件码 `auto_image_skipped:<code>`，不使任务失败。
- 前台标注：快照资产新增 `concept: true`（来自 `generatedConcept`），渲染层在图片后输出 `<small class="concept-note">`，文字按站点语言（en Illustrative / zh 示意图 / es fr de ja ar ru）。样式在新文件 `server/builder/concept.css`，**仅当页面出现该标注时**才追加进 `site.css`；工作台预览 iframe 固定加载该文件。product-grid 卡片在产品无图时才使用卡片条目上的示意图。
- **图片服务兼容（用户要求）**：`decodeGeneratedImage(response, fetchUrl?)` 支持 `data[0].url` 与聊天回复中的 HTTPS 图片链接；`downloadGeneratedImage` 只接受公网 HTTPS（`publicUrl` SSRF 校验、禁重定向、60 秒、10 MB 上限、本地 MIME 嗅探）。images 模式首次返回 400/422 时，用同一预留去掉 `n/size` 降级重试一次，最终最多计费 1 张。`generateImage` 新增可选第三参数 `{ originKey, fileLabel }`，原有调用不变；`imageBrief.composition` 新增 `logo`。

### 阶段 C：演示模式 + 候选事实
- `Site.demoMode`（默认 false）、`Site.autoImages`（默认 false）；`PATCH /sites/{id}/options`（管理员，不递增 revision，Agent 运行中返回 `STEP_BUSY`）。`siteDto` 仅在开启时输出这两个字段，关闭时 DTO 与快照形状不变。
- AI 建议事实：`server/src/services/fact-suggest.service.ts`，`POST /sites/{id}/fact-suggestions`（需 `consent: true`）→ Worker 任务 `catalog.suggest`，一次受 `reserve/settle` 保护的模型调用（结果先存 `pendingResult` 再结算，未知结果保留预留）。仅为缺失的 `company.founded/capacity/employees/factoryArea/exportCountries/customers/caseStudy/warranty` 与每个产品的 `product.specifications/warranty/leadTime/moq/capacity` 提建议；不建议认证。值逐字来自模型输出，写入 FactSheet：`status: candidate`、`source: { kind: "ai-suggested", runId, refId, label, quote, capturedAt }`，按 `originKey` 去重，已存在（待确认或已确认）的类型不再建议。`GET /fact-suggestions/{id}` 查询状态。
- 演示模式开启时：`queueAgent` 快照额外冻结 ai-suggested 候选（保留 `status: candidate` 与 `source.kind`），`assertSnapshot` 分别校验已确认事实与候选事实的修订，演示模式切换会使快照失效（`SOURCE_CHANGED`）；`validatePage` 新增 `allowDemoFacts`，只放行 ai-suggested 候选的引用校验，数字/年份/认证/产能/邮箱/措辞校验照常；提示词对候选标记 `demo: true` 并说明只能逐字引用。
- 门禁不放宽：`pageView` 对引用 ai-suggested 候选的页面追加 `DEMO_FACTS_UNCONFIRMED` 问题（页面显示为 blocked）；`reviewPage` 批准时显式返回 409 `DEMO_FACTS_UNCONFIRMED`；构建体检 `inspect` 因此报告该问题并 `SITE_NOT_READY`；已有的 `validVersion` 仍以 `VERSION_FACTS_CHANGED` 拒绝引用非 confirmed 事实的版本。前端把两者提示为“含未确认的演示数据”。
- 预览：私有页面预览在演示模式下页脚显示“演示内容，未经企业确认 · Demo content, not confirmed by the company”；站点工作台顶部显示演示模式提示。
- 事实库：`GET /facts?source=ai-suggested` 与前端“AI 建议”筛选；逐条/批量确认、拒绝沿用原接口；编辑 ai-suggested 事实保留来源并重置为候选（revision 递增），`POST /facts` 不能创建 ai-suggested 来源（400 `SOURCE_NOT_LOCAL`）；确认分支校验产品主体仍存在。
- 关闭演示模式后：新快照只含已确认事实；已引用候选的页面重新显示 `FACT_REFERENCE_STALE`。

> 注意：整站扩展（content 全站）仍要求试点首页与代表详情页已批准并有已接受的质量审查。引用演示数据的试点页面不能批准，因此**演示模式下可以预览设计提案与单页生成，但要扩展整站，需要先在事实库确认试点页面引用的事实**（或试点页面不引用演示数据）。这是不放宽审批门禁的直接结果。

### 阶段 D：质量基线审查
- `server/src/services/agents/quality-baseline.ts`：五项 1–5 分（首屏冲击、区块节奏、信息密度、可信度元素、转化路径），确定性规则基于冻结页面与隔离浏览器测量：首屏是否有图（1440 首个 section 的图片数）、标题词数与行数（有 `h1Height/h1LineHeight` 时）、相邻区块类型/框架重复与底色重复、首页区块数、每区块字数与高而空的区块、空白区块、带确认引用的 metrics 与 case-study/evidence/certifications、主行动、cta、产品发现与询盘目标。
- `reviewOutput` 新增可选 `scores`（可为 null）。只有本次审查确实把截图交给视觉模型（`visualInput=true`）时才与结构分取平均，`method: "structural+visual"`；否则 `method: "structural"`，前端写明“模型未查看截图”。
- 总分低于 `QUALITY_BASELINE_THRESHOLD`（默认 3.5）时，报告给出 `improvements`，并以 warning 级发现写入 findings（供“按审查改进”使用）；warning 不阻止接受审查，也不自动改写、批准或发布。审查结果新增 `baseline` 字段，前端 `agent-results.tsx` 展示。

### Verona 端到端验收步骤
1. 管理员打开组织「AI 图片设置」：baseUrl 填 `https://synapsea.co/v1`，模型填 `gpt-image-2.6-flare`，模式选 auto（或 images），在密钥框填入图片服务密钥（只在该页面输入，加密入库；不要写进任何文件）。
2. Verona 工作台 → 设置：开启“演示模式”和“AI 自动配图”。
3. 勾选同意后点击“生成 AI 建议事实”，完成后到事实库「AI 建议」筛选检查候选值。
4. 在同一设置页的「品牌 Logo」生成 Logo 候选，核对拼写后选用横版或方形；或上传真实 logo；不选则使用 SVG 字标。
5. 重新运行设计提案：确认首页与代表详情使用 precision、首屏有图（生成图带“示意图 / Illustrative”角标）、预览页脚显示“演示内容，未经企业确认”。
6. 运行质量审查，在审查报告中查看“质量基线评分”：未启用视觉模型时应显示“结构评分”。
7. 尝试批准引用演示数据的页面或构建/发布：应被拦截，提示“含未确认的演示数据”。
8. 在事实库逐条或批量确认（必要时先修改）AI 建议事实；重新批准页面、接受审查、扩展整站并构建发布。
