# S6 运行与验收

## 使用

1. Node >=22.23.4；按 README 启动 Docker Compose，登录已验证邮箱的组织账号。
2. 产品库准备产品并在站点地图添加相应产品页；确认事实、审核页面后进入站点“询盘设置”。
3. 审核自动隐私政策模板及已确认公司资料，设置通知成员（空选默认组织负责人），勾选启用及政策已审核并保存。AI 识别和 Turnstile 均可不启用。
4. 重新构建；登录预览中填写表单并测试。预览需 noindex，提交存档后在“询盘管理”查看；开发未配 SMTP 时通知显示开发状态并只记录脱敏通知编号。
5. 公网部署配置 PUBLIC_URL 为实际 HTTPS 管理台/API 地址、生产密钥、SMTP；通过现有 Cloudflare 发布流程发布该版本。开启 Turnstile 时将正式站、提供商预览及管理台预览域名加入该服务的允许主机名单。
6. 后台按站点/日期/状态/垃圾分数筛选，查看重复留言、附件，修改状态/添加备注，导出 CSV。关闭站点询盘开关可立即停收；重新启用/修改政策后重新构建发布。

## 配置与恢复

唯一新增环境变量 INQUIRY_TRUSTED_PROXY 同步 .env.example、production.env.example、compose.yaml，默认空。只有确实通过固定反向代理部署时填写其 IP/CIDR，且防火墙阻止绕过代理直连。PUBLIC_URL、SMTP_*、MAIL_FROM、CREDENTIAL_ENCRYPTION_KEY、STORAGE_ROOT 复用已有配置；不需要 CRM。

api/worker 必须共享 globalsite 数据库、密钥和私有存储卷。启动自动执行 s6-inquiries-v1 索引迁移，也可 npm run migrate。既有站点默认未启用，旧版本不变；需要重新构建获取隐私页、表单和脚本。不删除既有用户、站点或卷。

询盘计量无限额，但附件占用现有存储额度。SMTP 已知失败最多自动尝试 8 次，配置好后可在详情重试；未知发送结果不会盲重发，应先核对 SMTP 日志。没有有效收件人时显示 no_recipient，需修复成员/通知设置，历史记录仍在后台（本阶段不能自动补建其收件人）。不要把邮件正文、访问者数据、验证码或 Token 写入日志。

网关同进程但独立路由 /api/inquiry-gateway/v1，不使用管理台 Cookie。不要在代理侧附加任意 CORS 放行；需要转发 Origin，公开请求不能省略它。匿名预览仅限已验证的提供商版本域名，管理台预览使用短期签名头。不能通过手工登记任意域名绕过发布验证。

## 运营检查

隐私模板需要站点运营者结合实际业务与适用地区审核，特别是联系地址、第三方 AI、保留期限和权利请求处理。S6 不自动删除询盘或附件，不承诺已经过法律审查。可选 Cookie 默认关闭；无论访客国家如何都能拒绝，询盘仍可提交。PDF 只验证文件签名并私有下载，未提供杀毒保证。zip 手工部署暂不能自动获得匿名询盘域名授权。
