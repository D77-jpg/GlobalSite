# S5 运行与验收

## 使用

Node >=22.23.4；Docker 镜像使用22.23.4。保留原有 Mongo/storage 持久卷：

~~~sh
npm ci --ignore-scripts
npm run typecheck
npm run build
npm run lint
npm test
docker compose up -d --build --wait
npm run test:e2e
npm run test:quality
npm audit --audit-level=high
~~~

打开 http://localhost:5080/sites，选择站点 → 构建与发布。确认地图、审核页面，填写正式 HTTPS 网址，体检通过后构建。版本就绪可登录预览和下载 zip。Cloudflare 未配置时这些功能保持可用。

Cloudflare：新建 Direct Upload Pages 项目，在页面配置账户ID/项目/生产分支和 Pages Write Token。Token 只在密码输入框内暂存；保存后清空，不进入日志。配置自定义域名后按控制台指引修改DNS，检测HTTPS，再重建并发布。生产必须设置独立主密钥并按既有文档备份；没有新增环境变量。

首次部署自动创建 PublishingSettings、SiteVersion、SiteDeployment 索引和 s5-build-publish-v1 账本。不要删除现有用户、数据卷或覆盖 .env。已发布页面在事实修改后需主动重建发布；数据库不能自动撤销 CDN 已分发内容。

## 实测范围

- 本机：Windows Node24；后端测试使用临时 Mongo8.2.6 副本集。CI与Docker使用Node22.23.4，CI临时Mongo7.0.14。
- 真实 Astro 子进程构建，含图片WebP、两个内容页面、FAQ/表格与404；三模板逐页 HTML 校验。未真实调用付费AI。
- Docker普通用户曾发现Astro默认缓存写依赖目录失败，已修复为每任务独立可写缓存，并以真实容器浏览器流程保护。
- 本机拉取固定Node镜像曾遇Docker Hub解析/连接失败；本机已缓存镜像经 node --version 确认恰为22.23.4，补同版本标签后构建通过。没有改系统DNS或降低TLS验证。
- 预览在登录路径，HTML meta与HTTP头均noindex；正式zip正文无预览noindex；404单独noindex。
- 云发布使用模拟HTTP/适配器验证：Token加密和审计、用户角色权限、manifest上传、生产指针、HTTPS散列、模糊POST只核对、不重复创建、同目标Token更换、回滚复用原文件。未配置真实Cloudflare账号/域名，没有对外发布客户站点。

## 限制与恢复

- S6前询盘展示禁用，不会假装接收成功；联系方式只展示已审核引用事实。
- 关键词/事实质量与S4一样需要业务人员审核。没有资料不生成假的工厂、认证、案例。
- 版本/发布列表为最近100项；历史zip持续计存储，无自动版本删除。崩溃临时目录需确认无活跃任务后运维清理。
- 发布结果unknown时保持目标锁与额度预留，管理员使用“核对远端结果”；如Token过期，仅替换同目标Token后核对。禁止通过盲目新建部署或数据库改状态掩盖不确定结果。
- 外部Cloudflare操作可能在本站核验后改变内容；本站不提供持续一致性监控。真实云端/域名验收需客户配置Token与DNS后执行。
- full/production依赖均无high/critical；现有中风险告警不使用强制升级处理。
