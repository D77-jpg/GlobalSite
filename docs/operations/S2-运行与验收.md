# S2 运行与验收

本记录描述 GlobalSite feat/s2-foundation；GlobalCRM 只读，无提交或业务改动。S1 文档 PR #1 是已审核的前置设计，本分支基于该提交；若其尚未合并，先合并 #1，再审查 S2 的工程增量。

## 启动与降级

- docker compose up -d --build：api、worker、Mongo 单节点副本集；默认 http://localhost:5080。
- api 提供 web/dist 与 /api/v1，worker 处理独立邮件任务。Mongo 仅数据库 globalsite。
- 开发注册→页面“开发邮件预览”→验证→登录；不预设管理员。
- SMTP 缺失时开发日志仅通知编号，正文/验证码通过一小时有效能力链接查看；生产不返回预览，邮件等待配置。
- AI 缺失时账号/组织/成员/文件功能正常；AI 页面仅管理员可配置，每组织独立密钥和额度。
- PUBLIC_URL 必须与浏览器访问地址一致；本地 npm run dev 是 5173，Compose 是 5080。已有 .env 不会自动切换这两个地址。
- API_PORT 可改本机端口，PUBLIC_URL 必须同步；Mongo 27018 仅供开发。
- 生产必须使用 HTTPS/独立主密钥/SMTP，不使用自动生成的开发 .local-key。

## 已执行的验证

- typecheck、build、lint，以及隔离的 MongoDB 副本集测试。
- 后端真实 HTTP 测试按本站 OpenAPI 校验响应结构；无 CRM 连接调用，因此未建立 CRM 草案能力的测试假象。
- 桌面与 390px 移动浏览器：注册、邮箱验证、登录、组织保存、成员邀请、用量、中英切换、两步验证、再次登录；移动无横向溢出，截图已人工查看。
- Compose 服务健康，实际页面/API 经浏览器访问，未连接 CRM 数据库。
- 本机首次 Mongo 测试程序下载较大，使用复制到本站 node_modules 缓存的 MongoDB 8.2.6 执行；测试源码和 CI 默认 7.0.14，均为临时数据库。没有提交本机程序路径或二进制。
- Docker Hub 首次拉取网络失败，通过 mirror.gcr.io 官方缓存获取相同 Node 22 基础镜像；没有修改 Docker 全局配置。8080 已被占用，采用 5080，不停止原服务。

## 安全回归范围

组织 A 不能读写 B 的记录；无租户查询、聚合跨库/跨集合、批量写入及修改租户键被拒绝；只读/编辑不能管理组织与提供商；刷新重放吊销、设备会话撤销、CSRF/Origin、邮箱验证与 OTP 单次/过期/次数限制、密码锁定/重置/authVersion、长密码无截断碰撞；并发席位/额度不得超限；加密篡改和错误 tenant AAD 被拒绝；任务租约接管与旧持有者完成被拦；图片魔数/组织资源隔离；AI 配置不出密钥、计量幂等；审计与分页限定当前组织。

## CI

GitHub Actions 在 Node 20.19 执行 npm ci、typecheck/build/lint/test、全量依赖审计（high/critical 阻断）、Gitleaks；浏览器作业从 Compose 运行真实页面并保存合成测试账号截图。所有依赖锁定在 package-lock.json，安装和镜像构建跳过依赖 postinstall 脚本。

## 限制和后续

1. React Router 按要求保持 6，当前两项 moderate 告警；本站不使用 SSR hydration，返回路径严格白名单，不擅自升级 7。仍需持续跟进修补，不能宣称无漏洞。
2. 实际 SMTP 投递和真实模型计费需部署者配置后验证；测试使用模拟 AI 服务，不包含真实密钥或付费调用。
3. S2 单组织一个默认 OpenAI 配置，仅官方地址；多提供商切换与通用 DNS pinning 传输后续实现。
4. 存储为本地持久卷；未接 S3/MinIO/杀毒/文档解析。故障后的孤立文件与不确定 AI 预留需要运维核对，后续加入定期对账。
5. 套餐为固定额度，无支付/订阅渠道或自动升级；当前限制按月/存储累计执行，试用到期运营流程后续补齐。
6. S3 产品与事实、S4 内容/模板/Agent、S5 发布、S6 公开询盘、S7 CRM 均未实现。本站对接契约仍只引用 CRM 唯一文件。
7. 初始迁移需要事务型 MongoDB，不能连接无副本集的 standalone Mongo；默认 Compose 已满足。
8. 源仓库无 LICENSE，复制来源保留；许可发布方案仍由所有者决定。
