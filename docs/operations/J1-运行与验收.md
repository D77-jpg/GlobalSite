## 部署顺序

1. CRM 使用支持事务的 MongoDB 副本集，沿用原库名。先执行 C2 integration:credential -- migrate，再 npm run migrate 应用009索引。运行 CRM API 与 Worker。
2. CRM 部署示例配置 GLOBALSITE_ATTACHMENT_ORIGINS 为本站公开 API 精确HTTPS来源，用于异步拉取询盘附件。缺失时询盘仍存档，附件明确失败，不任意下载。
3. 本站保留独立 globalsite、共享 api/worker 主密钥与存储；配置 CRM_ALLOWED_ORIGINS 为CRM精确HTTPS来源，执行 npm run migrate 创建j1-s7-crm-v1索引并启动Worker。两边不互访数据库。
4. CRM 项目管理员生成 GlobalSite 凭证（需要的scope以CRM契约及预设为准），在本站组织管理员连接页面填写地址/项目ID/凭证。秘密仅显示一次，切勿放URL或浏览器存储。
5. 同步后审阅候选事实与产品差异。旧站重新审核隐私模板并构建，新版告知才允许询盘投递；旧告知询盘不会被自动历史补推。
6. 查看连接最近同步时间、失败记录和询盘CRM状态；凭证失效先在CRM轮换，再本站更新/测试，队列恢复。同项目原键重试，不手工改投另一项目。

本地 loopback 例外须双方显式启用且仅非生产；不要在生产启用。无CRM配置仍可独立使用。没有真实外部服务凭证，本次没有生产部署、真实发信或Cloudflare发布。
